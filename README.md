# LMS

Учебная платформа онлайн-курсов: каталог, регистрация, создание и публикация курсов, покупка за внутренний баланс, чтение уроков и сохранение прогресса.

Проверено 26 ноября 2026 года: frontend собирается, backend проходит `clean verify` и 21 тест. Основной сценарий проверен также через браузер на отдельной тестовой БД. Это рабочая учебная версия; реальные платежи, возвраты и размещение в интернете пока не реализованы.

## Локальный запуск

Нужны Docker Desktop с работающим Linux engine, JDK 21 и Node.js 22.12+; проверка выполнена на Node.js 24.16. `JAVA_HOME` должен указывать на JDK, а не JRE.

В PowerShell из корня проекта:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-21'
docker compose up -d --wait postgres
.\mvnw.cmd clean spring-boot:run
```

Перед первым запуском обновлённого приложения остановить прежний backend в IDEA. `clean` удалит старые скомпилированные классы после переноса и удаления исходников. Backend слушает порт 8080. Flyway выполняется до генерации jOOQ, отдельная команда `flyway:migrate` для обычной сборки больше не нужна.

В другом терминале из того же каталога:

```powershell
npm ci
npm run dev
```

Открыть [http://localhost:5173](http://localhost:5173). Vite перенаправляет `/api` на backend. При занятом 5173 запуск остановится с понятной ошибкой; автоматически менять порт и ломать CORS он не будет.

Для локальной работы профиль `local` включён по умолчанию. Его БД: `localhost:5432/lms`, пользователь `postgres`, пароль `password`. Демоаккаунты создаются только в `local`:

| Роль | Email | Пароль при первоначальном создании |
| --- | --- | --- |
| Учитель | teacher@lms.com | teacher |
| Администратор | admin@lms.com | admin |
| Ученик | Зарегистрировать через интерфейс | Собственный пароль |

Существующие аккаунты, пароли и балансы инициализатор не сбрасывает. При регистрации появляется кошелёк с нулевым балансом. Для проверки покупки удобно создать бесплатный опубликованный курс. Пополнение за реальные деньги отсутствует.

## Настройки окружения

`.env.example` содержит образец для Vite и Compose. Копировать его в `.env` необязательно, если подходят локальные значения. Spring Boot сам файл `.env` не загружает: задавать серверные переменные в PowerShell или конфигурации запуска IDEA.

| Переменная | Назначение |
| --- | --- |
| `DB_URL`, `DB_USER`, `DB_PASSWORD` | JDBC-подключение backend и Maven-плагинов |
| `JWT_SECRET` | Подпись JWT; известный учебный ключ допустим только в `local` |
| `LMS_ALLOWED_ORIGINS` | Разрешённые адреса интерфейса через запятую; по умолчанию `http://localhost:5173` |
| `VITE_API_URL` | Адрес API при сборке frontend; по умолчанию `/api/v1` |
| `LMS_API_PROXY_TARGET` | Адрес backend для локального Vite proxy; по умолчанию `http://localhost:8080` |
| `DB_NAME`, `DB_PORT` | Имя БД и опубликованный порт контейнера Compose |

Внешний запуск требует явно выбрать профиль, например `SPRING_PROFILES_ACTIVE=prod`, задать отдельные реквизиты БД и случайный `JWT_SECRET`. Смена ключа делает старые JWT недействительными. `prod` здесь отключает локальные значения и демо-инициализатор, но сам по себе не настраивает HTTPS, резервные копии и размещение.

Изменение `POSTGRES_PASSWORD`/`DB_PASSWORD` в Compose не меняет пароль уже созданной БД внутри существующего тома. Не удалять том ради смены настройки.

## Проверки в отдельной БД

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-21'
docker compose --profile test up -d --wait postgres-test
.\mvnw.cmd -B -Ptest-db clean verify
npm run build
docker compose --profile test stop postgres-test
```

Тестовая БД — `localhost:55432/lms_test`, пароль `lms_test`. Она хранится в `tmpfs` и очищается тестами; не использовать её для своих данных. Основная БД `lms` этими тестами не очищается. Проверка перед `TRUNCATE` допускает только локальную БД с именем `lms_test`.

Maven-профиль `test-db` выбирает БД для миграций и генератора jOOQ; Spring-профиль `test` включают сами тестовые классы. Это разные механизмы. `-Ptest-db spring-boot:run` само по себе не переводит запущенный сервер на тестовую БД. При ручной проверке отдельного сервера нужно явно задать `DB_URL`, `DB_USER` и `DB_PASSWORD`.

Проверяются права и видимость черновиков, регистрация и кошелёк, покупка и журнал списаний, повторные и одновременные запросы, откат всей покупки при сбое, принадлежность урока курсу, прогресс и границы модулей.

Один тест намеренно вызывает ошибку ограничения `test_reject_enrollment`: он доказывает откат баланса, журнала и записи на курс. Стек этой ошибки в тестовом логе ожидаем; итог проверки — `Failures: 0, Errors: 0`.

## API основного сценария

Все пути ниже начинаются с `/api/v1`. Для защищённых запросов используется `Authorization: Bearer <token>`.

| Метод и путь | Доступ |
| --- | --- |
| `POST /users/register`, `POST /users/login` | Публичный |
| `GET /users/me`, `PATCH /users/me` | Текущий пользователь |
| `GET /courses?q=&limit=12&offset=0` | Опубликованный каталог |
| `GET /courses/{id}` | Опубликованный курс; черновик виден только автору |
| `GET /courses/authored` | Учитель/администратор, только собственные курсы |
| `POST /courses`, `POST /courses/{id}/lessons`, `POST /courses/{id}/publish` | Учитель/администратор; изменять существующий курс может его автор |
| `GET /billing/wallets/me` | Кошелёк текущего пользователя |
| `POST /purchases` | Покупка по JSON `{ "courseId": "UUID" }` |
| `GET /courses/my` | Активные покупки и реальные счётчики прогресса |
| `GET /courses/{id}/syllabus` | Активный ученик или автор |
| `GET /courses/{id}/lessons/{lessonId}` | Активный ученик или автор |
| `POST /courses/{id}/lessons/{lessonId}/complete` | Активный ученик; повтор безопасен |

Автор просматривает собственные уроки без покупки. Предпросмотр не создаёт ученический прогресс. Роль ADMIN сейчас не даёт автоматического права редактировать чужие курсы.

## Ограничения версии

Нет настоящего платёжного шлюза, возвратов, загрузки видео, редактирования и удаления уроков, интерфейса архивации, восстановления пароля и автоматического развёртывания. Ссылка на видео рассчитана на прямой HTTP(S)-ресурс, поддерживаемый браузерным `<video>`, а не произвольную страницу видеохостинга. Мобильная версия отдельно не проверялась.

Покупка намеренно остаётся одной транзакцией с общей БД; SQL в `feature.purchase` пока связывает несколько предметных модулей. Вариант дальнейшего разделения описан в разборе. Исходники подготовлены для GitHub; репозиторий автоматически не создаётся и push не выполняется.
